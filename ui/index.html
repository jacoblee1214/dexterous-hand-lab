What A–E compute and why a result is valid/invalid

Shared prior: the current 40 mm setting is a fixed, known sphere radius. Every mode estimates only the 3D center; radius is never fitted.

A · RGB-only: calibrated RGB mask boundary rays minimize tangent-to-known-radius residuals, with penalties for sphere intrusion into known background. Unknown/hand-occluded pixels are excluded.

B · Tactile representative: each active scalar channel is converted through its pressure/indentation calibration into one representative point. It minimizes point-to-sphere radial residuals.

C · Fusion representative: combines A and B using configured modality weights after each modality is standardized and normalized by sample count.

D · Fusion finite-patch: replaces each tactile point with the calibrated finite sensor surface. Its residual is zero when any sampled patch point can lie on the sphere; otherwise it is distance to that feasible radial interval.

E · Reliability-aware Fusion v2: keeps one latest measurement per named sensor, checks RGB/tactile observability, cross-modal standardized residuals, and tactile information in the weakest RGB direction. It reports genuine fusion, RGB-only fallback, tactile-only fallback, or invalid explicitly.

All modes use deterministic RGB-cone or tactile algebraic initialization and a Huber robust loss. A finite patch cannot identify the exact contact location because one scalar channel reports no within-patch coordinates. Scalar pressure is a magnitude-like normal response, not a measured 3D force vector or direction.

Input / prediction / evaluation boundary

Input: calibrated RGB visibility plus named scalar tactile patches in a declared static fixture frame. Prediction: a rotatable object-centric dense SDF zero surface. GT is evaluation-only and hidden by default. No radius, object identity, CAD, GT pose, mesh, contact point or contact normal enters the proposed methods.
